Approach

Process first, automation second

I don't automate something just because it can be automated. I learned operations through procurement, where every step has a cost, so I start by understanding the process and the real problem, and only then build the system.

  1. 01

    Spot the repeat

    Find the check, copy-paste or chase someone does every day, and time it.

  2. 02

    Fix the data

    Make one source of truth, then connect the tools to it.

  3. 03

    Test on one client

    Run it for a single client and fix what breaks first.

  4. 04

    Roll out with an SOP

    Document it so the team can run it without me.
